# US-0186: one xz library and the other formats unchanged

> Spec: SPEC-0084 (sdlc/specs/SPEC-0084-tar-family-bounded-decoding/)
> Nature: FEAT
> Priority: P2
> Depends on: US-0185
> min_tier: 2
> Files touched: 5
> Closes spec: no

## Objective
The product reads xz with one library: `lzma-rs` leaves the manifests and the two test fixtures that still used it switch to liblzma's encoder. Plain `.tar`, `.zip`, the tar family within the limits and the unsupported `.tbz2` behave exactly as before.

## Requirements covered
- SPEC-0084/FR-NEW-011 (partial: plain `.tar`, `.zip`, the tar family within the limits and `.tbz2`): THE archive extraction SHALL extract plain `.tar`, `.zip`, `.7z`, RAR, bare `.gz`, `.bz2` and `.xz` files exactly as before this increment, SHALL answer a compressed tar archive within the limits with the same destination, counts and audit line as before, SHALL check the two limits on the files' sizes as before, and SHALL keep refusing `.tbz2` and every other unsupported extension with `ERR_NOT_SUPPORTED` and `unsupported archive extension: '<extension as typed>'`.
- SPEC-0084/FR-MOD-002 (partial: one xz library: `lzma-rs` removed): THE archive extraction SHALL decode a `.tar.xz` or `.txz` file with the rules of a bare `.xz` file (FR-NEW-006 to FR-NEW-009).

## Design excerpt
### Decisions
- **DEC-004 (SPEC-0084):** decoders: `.tar.gz`/`.tgz` `flate2::read::GzDecoder`, `.tar.bz2`/`.tb2` `bzip2::read::BzDecoder` (single member and single stream, as today), `.tar.xz`/`.txz` `archive_single::decoder(SingleFormat::Xz, bytes)` (liblzma explicit stream decoder with `CONCATENATED | TELL_UNSUPPORTED_CHECK`, SPEC-0082 DEC-003); a plain `.tar` is not decompressed and gets no bound. Read errors map to `corrupt(<format>, e)`; `ReadError::Init` maps to `ToolError::internal("cannot start the tar.xz decoder: <e>")`. **Obliged by:** SPEC-0084/FR-MOD-002, FR-NEW-006, FR-NEW-007, FR-NEW-008, FR-NEW-009, FR-NEW-011 (spec 3.2: several gzip members or bzip2 streams stay out). **Rationale:** the bare xz decoder already implements every `.tar.xz` rule of the spec (measured in SPEC-0082 DEC-003: several streams, padding of a multiple of 4, BCJ, SHA-256 accepted; `.lzma`, unknown check, junk refused). **Alternatives considered:** `MultiGzDecoder`/`MultiBzDecoder` for the tar family (a behavior change the spec excludes); keeping `lzma-rs` (refuses padding, BCJ, SHA-256, several streams: the defect of BL-0132). **Source:** spec constraint and existing code. **Evidence:** `crates/core/src/tools/archive_single.rs:64-86`, `crates/core/src/tools/archive.rs:727-749`, `liblzma-0.4.9/src/stream.rs:1320`.
- **DEC-007 (SPEC-0084):** `lzma-rs` is removed from `Cargo.toml` `[workspace.dependencies]` and `crates/core/Cargo.toml`; the two test fixtures that used `lzma_rs::xz_compress` (`archive.rs:1993-1995`, `archive_single.rs:2116-2121`) use `liblzma::write::XzEncoder::new(Vec::new(), 6)`, assertions unchanged. **Obliged by:** SPEC-0084/FR-MOD-002 ("one xz rule"; production no longer calls `lzma-rs` after US-0183). **Rationale:** a production dependency used by tests only is dead weight in every build; the spec names the removal as a design decision (14.3). **Alternatives considered:** keeping it as a dev dependency (still two xz encoders in the tree); keeping it as is. **Source:** spec design input. **Evidence:** `rg -n 'lzma_rs|lzma-rs'` (5 hits: two manifests, `archive.rs:745`, `:1994`, `archive_single.rs:2120`).
- **DEC-013 (SPEC-0084):** stories US-0185 and US-0186 hold tests that turn green with an earlier story's code (green on arrival); each is proven by a mutation reasoned to change that test's observable outcome, listed in the story. **Obliged by:** n/a (no code impact): story planning. **Rationale:** precedent US-0172, US-0180 to US-0182. **Alternatives considered:** fewer, larger stories over the tier 2 budget. **Source:** design. **Evidence:** `git log` of US-0180 to US-0182.
