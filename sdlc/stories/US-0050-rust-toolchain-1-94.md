# US-0050: move the toolchain to 1.94.1 and lock aws-sdk-s3 1.152.0

> Spec: SPEC-0042 (sdlc/specs/SPEC-0042-rust-toolchain-1-94/)
> Nature: DEBT
> Priority: P1
> Depends on: main
> min_tier: 2
> Files touched: 6
> Closes spec: yes

## Objective
Raise the Rust floor and pinned channel to 1.94.1 so aws-sdk-s3 1.152.0 resolves, which removes lru 0.12.5 and the RUSTSEC-2026-0002 acceptance. No behavior change.

## Requirements covered
- SPEC-0042/DR-001: The workspace SHALL declare `rust-version = "1.94.1"` and `rust-toolchain.toml` SHALL pin `channel = "1.94.1"`.
- SPEC-0042/DR-002: `Cargo.lock` SHALL resolve `aws-sdk-s3` to 1.152.0 and SHALL NOT contain `lru` 0.12.5.
- SPEC-0042/DR-003: `.cargo/audit.toml` SHALL NOT list RUSTSEC-2026-0002, and the reason of RUSTSEC-2026-0253 SHALL name only tantivy 0.26.2.
- SPEC-0042/DR-004: The server SHALL produce, for every input covered by the existing test suite, byte identical observable output before and after this change.

## Independent Test
`make check` green, then `make test-e2e-full` green (MinIO exercises the new S3 client); `cargo tree -i lru@0.12.5` reports no match.

## Design excerpt
### Decisions
- DEC-001: pin exactly `1.94.1` (aws-sdk-s3 1.152.0 declares it; `toolchain_pin.rs` needs channel == rust-version).
- DEC-002: `cargo update -p aws-sdk-s3 --precise 1.152.0`, not a bare update (a bare `-p` stayed on 1.119.0; a full update is unrelated churn).
- DEC-003: one story, because the lock, audit list and its test must move together.

| `Cargo.toml` | `:8` `"1.88"` to `"1.94.1"`; reword the `:100` "1.88 MSRV" comment |

| `Cargo.lock` | regenerated by the DEC-002 command |

### Existing patterns
