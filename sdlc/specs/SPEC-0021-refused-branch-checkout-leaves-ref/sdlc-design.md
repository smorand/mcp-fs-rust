## 2. Approaches
### Chosen: write the branch only after the checkout is applied
When `checkout` is true, `branch_create` admits and applies the checkout first, then writes the branch
row, the on disk ref and HEAD. When `checkout` is false the order is unchanged. Fixes at the root cause
site `crates/core/src/tools/git.rs:2292`. One function changes.
### Rejected: delete the ref on the error path
The `stash_save` pattern (`git.rs:6907-6909`). Rejected (DEC-001): it needs a compensating delete on
every error branch, and a failing delete would still leave the ref.

## 3. Architecture
Only `branch_create` (`crates/core/src/tools/git.rs:2239-2306`) changes. It already holds the repo write
lock (`git.rs:2251`) for the whole call, so no reader sees an intermediate state either way.
`merge::charge_and_apply` (`crates/core/src/git/merge.rs:675-693`) is unchanged and already refunds the
session charge on apply failure (`merge.rs:689-691`).

## 7. Compatibility and risks
Residual: if the branch row write fails after a successful apply, the volume holds the target tree with
HEAD still on the old branch, which the next `git.status` shows as uncommitted changes. Accepted: the
same window exists in `git.branch_switch` for HEAD. Rollback: revert the commit.

## 10. Decisions log
- **DEC-001:** with `checkout: true`, call `merge::charge_and_apply` before `entry.db.set_ref` and
  `repo.reference`; write the branch, then HEAD, only on success. **Obliged by:** SPEC-0021/BR-001,
  BR-002, BR-003. **Rationale:** nothing to undo on any error path. **Alternatives considered:**
  delete on error (stash_save pattern). **Source:** design. **Evidence:** `git.rs:2292-2303`.
- **DEC-002:** BT-011 induces the apply failure by removing the target blob of `/k.txt` from the git
  object store (blob key `git:{sha}`) before the call, so `apply_changes_atomically` fails reading it
  (`merge.rs` `find_blob` in pass 2); any equivalent fault reachable from the test harness without a
  production hook is acceptable. **Obliged by:** SPEC-0021/BR-002. **Rationale:** no production test
  hook. **Alternatives considered:** a fault injection trait on `VolumeClient` (new production surface,
  rejected). **Source:** design. **Evidence:** `crates/core/src/git/merge.rs` `apply_changes_atomically`.
- **DEC-003:** all seven BT tests live in `quota_e2e.rs`, named `spec_0021_bt_0NN_*`, reusing the `Vc`
  harness. **Obliged by:** SPEC-0021 tests 4.1 to 4.3. **Rationale:** the harness already builds the
  over limit state. **Alternatives considered:** the `git.rs` test module. **Source:** existing code
  `quota_e2e.rs:2445`. **Evidence:** n/a.
