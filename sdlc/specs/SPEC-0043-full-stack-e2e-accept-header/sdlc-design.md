## 2. Approaches
### Chosen: fix at the root cause site
Add the `Accept` header at the three `/mcp` POST sites of the test helpers (`establish_session` twice, `call_tool` once), through one shared constant so the value is written once. Pros: matches the root cause, 1 file, no server change. Cons: none. Best suited when the server contract is right and the client is wrong.
### Rejected: default header on the shared `reqwest::Client`
`reqwest::Client::new()` at `crates/core/tests/full_stack_e2e.rs:378` would carry the header on every request, REST included. Rejected, DEC-002.
### Rejected: relax the server's Accept check
Rejected, DEC-003.

## 3. Architecture
One test file. `establish_session` (`full_stack_e2e.rs:157-197`) and `call_tool` (`:214-`) build POSTs to `{base}/mcp`; each gains `.header("Accept", MCP_ACCEPT)`. Server side (rmcp 3.5.0, `LocalSessionManager`, `legacy_session_mode: true`, `crates/core/src/app.rs`) is untouched.

## 5. Contracts and interfaces

- No public surface changes. Server 406 behavior for a missing `Accept` stays (rmcp `tower.rs:1991-2001`).

## 10. Decisions log
- **DEC-001:** keep the fix inside the existing test file and add no dependency. **Obliged by:** SPEC-0043/BR-001, BR-003. **Rationale:** root cause is local to the test helpers. **Alternatives considered:** a shared test support crate (rejected: one file, YAGNI). **Source:** existing code `crates/core/tests/full_stack_e2e.rs:169`. **Evidence:** `rg -n -i accept crates/core/tests/full_stack_e2e.rs` is empty.
- **DEC-002:** set the header per `/mcp` request through `MCP_ACCEPT`, not as a client wide default. **Obliged by:** SPEC-0043/BR-002 (scope is `/mcp` only). **Rationale:** the REST plane must keep being exercised with the headers a real REST caller sends; a global default would hide a REST content negotiation regression. **Alternatives considered:** `ClientBuilder::default_headers` at `:378`. **Source:** design. **Evidence:** spec edge case table, REST calls unchanged.
- **DEC-003:** leave the server and its 406 as is. **Obliged by:** SPEC-0043/BR-003. **Rationale:** the check is the rmcp contract and every other client complies. **Alternatives considered:** loosening the server (rejected: changes a public contract to fix a test). **Source:** existing code `rmcp-3.5.0/src/transport/streamable_http_server/tower.rs:1991-2001`, `crates/agent/src/mcp.rs:116`. **Evidence:** same.
- **DEC-004:** one story carries the whole spec (reproduction, fix, closing). **Obliged by:** SPEC-0043/BR-001..BR-003. **Rationale:** 2 files, 1 behavior; splitting would leave a red or test-less main. **Alternatives considered:** separate doc story (rejected: 1 line). **Source:** design. **Evidence:** n/a.
