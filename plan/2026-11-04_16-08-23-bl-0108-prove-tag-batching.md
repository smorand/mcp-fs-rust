## Summary
The batching loop in `fetch_into_incoming` (`crates/core/src/git/remote.rs:1583-1595`) cannot be proven red over a `file://` remote, because libgit2's local transport sends every tag object whatever the refspecs ask for (the limit recorded in the comment at `crates/core/src/tools/git.rs:26220-26222`). The HTTP double of SPEC-0078 is backed by the real `git upload-pack`, which honours `want` lines, so a 501-tag fetch through it makes the second batch observable. Add that test, prove it red by mutation, delete the entry.
