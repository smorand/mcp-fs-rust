# Discovered drift: git.* #[tool] methods depend on the old ToolRegistry internally

> Discovered during: US-0005 (migrate git.* core tools)
> Originating register entry: none (new discovery, not a DDRIFT-001 surplus)

## What happened

`tools/git.rs`'s git handlers are private free functions, not a shared public engine like
`core::fs_ops`. To avoid duplicating thousands of lines of git/merge/rebase logic, US-0005's
implementation made each new `#[tool]` method dispatch by name through a `ToolRegistry` instance
built from `crate::tools::git::register()` (`crates/core/src/mcp/server.rs`, `git_tools:
Arc<crate::mcp::ToolRegistry>`).

## Why it matters

DR-003 requires `crates/core/src/mcp/{mod,registry,schema,args}.rs` to be deleted in full once
DR-002 is complete, with "no `ToolRegistry`... symbol SHALL remain referenced outside test code."
As committed, the 39 git.* `#[tool]` methods cannot survive that deletion unmodified: they hold a
live `Arc<crate::mcp::ToolRegistry>` and call into it.

## Resolution required at US-0009 (DR-003)

Before deleting `mcp/registry.rs`, the git.* `#[tool]` methods in `server.rs` must be refactored to
call the underlying git engine logic directly (promote the necessary free functions in
`tools/git.rs` to `pub(crate)` and call them straight, the same pattern `fs.*`/`admin.*`/`search.*`
already use via `core::fs_ops`), rather than re-entering `ToolRegistry`. This is additional scope
for US-0009 beyond "delete 4 files": it is a prerequisite refactor of `server.rs`'s git section,
owed by DR-003's own "no ToolRegistry symbol remains" clause.

## Not a spec edit

Logged per Invariant 6; `spec.md` and the stories are not modified. US-0009's implementer is
instructed explicitly (out of band, via this run's task prompt) to perform this refactor before
deleting the old module files.

## Addendum (US-0006): scope extended to git.auth* + git.pr_*

US-0006's 10 new `#[tool]` methods (`git.auth`, `git.auth_revoke`, `git.auth_status`,
`git.token_set`, `git.pr_create`, `git.pr_diff`, `git.pr_get`, `git.pr_list`, `git.pr_merge`,
`git.pr_review`) used the same `ToolRegistry`-dispatch shortcut as US-0005, rather than direct
extraction, because `tools/git_auth.rs` and `tools/git_pr.rs`'s handlers are private free functions
wired to a process-wide OAuth token store singleton (`git_auth.rs`'s `TOKENS: OnceCell`) and an
injectable `ProviderClient` seam (`git_pr.rs`'s `register_with`), too large to safely re-plumb as
`pub(crate)` free functions within this story's bounded scope. `McpServer::new` now also calls
`tools::git_auth::register` and `tools::git_pr::register` into the same `git_tools` registry
US-0005 built. This extends the resolution owed at US-0009 (DR-003) to cover all 49 `git.*` tools
(the 39 core + these 10), not just the 39: before deleting `mcp/registry.rs`, US-0009 must refactor
every `git.*`-family `#[tool]` method in `server.rs` to call the underlying engine directly,
including promoting the OAuth store accessor and the provider client resolution to callable
`pub(crate)` functions.
