# Discovered drift: session manager choice voids DDEC-001's premise

> Discovered during: US-0001 (DDRIFT-001 verification)
> Originating register entry: DDRIFT-001

## Spec says

Section 5 / Section 7 step 3: the migrated server uses `NeverSessionManager` with
`legacy_session_mode: false`, and under that configuration `initialize` becomes mandatory
(DDEC-001, DR-009's `-32600` response for a bare `tools/call`).

## What was found

Reading `rmcp` 3.5.0's actual vendored source (not context7-derived docs, per DDRIFT-001's own
resolution instruction):

- `NeverSessionManager` is documented (`session.rs:14-16`) as "used when legacy session mode is
  disabled."
- With `legacy_session_mode: false`, every request — including the very first one — is dispatched
  through the stateless `serve_directly_with_ct` path (`tower.rs:2270-2290`), with **no**
  `initialize` handshake required at all.
- With the default `legacy_session_mode: true` instead, `NeverSessionManager` cannot complete
  `create_session`, so the pairing the spec planned (`NeverSessionManager` + `false`) is the only
  one that type-checks, and it produces the opposite of DR-009's intended behavior.

So DDEC-001's "initialize becomes mandatory" break, as the spec's exact planned configuration would
produce it, does not hold: that configuration gives a *weaker* break (no initialize needed at all),
not the one DR-009/DT-001 specify.

## Decision

User decided (2026-10-03, this run): keep the spec's original intent — `initialize` IS mandatory,
DR-009's `-32600` response for a bare pre-`initialize` call stands — by changing the planned session
manager from `NeverSessionManager` to `LocalSessionManager`, with `legacy_session_mode: true`. This
reproduces the mandatory-handshake behavior DEC-107/DDEC-001 originally wanted, using the
configuration that actually has that effect in rmcp 3.5.0's real source, rather than the one the
spec named that does not.

## Scope of the correction

This is an implementation-detail correction, not a change to the declared intent: DR-008, DR-009,
DR-010, DT-001 and Section 4's compatibility table rows all stand as written — only the concrete
session-manager/legacy-mode pairing used to realize them changes, from
(`NeverSessionManager`, `legacy_session_mode: false`) to (`LocalSessionManager`,
`legacy_session_mode: true`). Every later story (US-0008 in particular, which performs the
transport swap) must use the corrected pairing.

## Not a spec edit

Per Invariant 6 / Section D, `spec.md` and the stories are not modified to reconcile this. This
drift file is the record; the correction is carried forward by every implementer story picking up
US-0008 and by this run's own continuation.
