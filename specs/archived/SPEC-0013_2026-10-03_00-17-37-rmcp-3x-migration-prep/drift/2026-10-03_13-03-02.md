# Discovered drift: optional web.*/context7.*/sqlite.*/db.*/doc.* tool families are not part of
McpServer and become unreachable via MCP after the transport swap

> Discovered during: planning US-0012 (catalog-only migration for non-contract families)
> Originating register entry: none (new discovery)

## What was found

`crates/core/src/tools/all.rs`'s `register_all` conditionally registers five more tool families
behind off-by-default feature flags (`features.web`, `.context7`, `.sqlite`, `.db`, `.doc`, all
`false` by default per `cli.rs:132-135` and commented out in `config/local.yaml`). None of the
five is part of the 94-tool contract this spec migrates (`TOOL_CONTRACT.txt`,
`tool-contract-golden.json`), and none was in Section 2's occurrence sweep.

Before US-0008, these families were reachable over MCP because the old hand-rolled
`mcp_endpoint` dispatched through the full `AppState.registry` (every registered family,
contract or not). US-0008 replaced that route with `rmcp`'s `StreamableHttpService` wrapping
`McpServer`, whose `#[tool_router]` only contains the 94 contract tools (+4 search.*). If any
deployment runs with `--web`/`--context7`/`--sqlite`/`--db` set, those tools are now silently
unreachable over MCP — a real behavior regression, not one of Section 5's two declared breaks,
and not covered by DR-006's exclusions.

## Assessment

Low practical risk (all five are off by default, no evidence of a production deployment enabling
them, per `config/local.yaml`'s own commented-out block), but a real, undeclared gap in the
migration's completeness for anyone who does enable them.

## Resolution for this run

Bounding the scope: US-0012 will still give these five families a catalog-only, ToolRegistry-free
path (so the final `mcp/registry.rs` deletion is not blocked, and `/api/swagger.json`'s coverage
of them is preserved if they're reachable via REST at all), but will NOT build `#[tool]` methods
for them on `McpServer` — that would mean importing optional, non-contract, experimental surface
into the exact contract (`TOOL_CONTRACT.txt`'s 94) this spec exists to migrate faithfully, which
is scope the spec never authorized.

## Not a spec edit

Per Invariant 6 / Section D, `spec.md` is not modified. This finding is carried into Phase 6.5 of
this run's final report as an open item: re-enabling MCP reachability for these five optional
families, if ever needed in production, requires its own follow-up (either a dedicated spec, or
an explicit decision that MCP access to them is no longer offered going forward).
