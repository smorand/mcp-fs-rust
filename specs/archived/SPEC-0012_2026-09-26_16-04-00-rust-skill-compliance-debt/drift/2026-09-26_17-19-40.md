# Discovered drift — 2026-09-26 17:19:40

## DDRIFT-002: `figment::providers::Yaml` cannot preserve the existing duplicate-host rejection

**Originating requirement:** DR-005 (config resolution internals), specifically the clause
"`ServerConfig::load`... SHALL parse the YAML file via a `figment::providers::Yaml` provider".

**What the spec expected:** swap `ServerConfig::load`'s parser from `serde_yaml::from_str` to
`figment::providers::Yaml`, preserving DR-006's byte-identical behavior, proven by the existing test
suite passing unmodified (DT-003 names the 5 `expand_env` tests explicitly as the compatibility proof;
DR-006/DR-007 extend that to "every input covered by the existing test suite").

**What implementation found:** `figment::Figment::extract()` always materializes an intermediate,
keyed `figment::value::Value` (effectively a map) from every provider before handing it to the
target's `serde::Deserialize` impl, because that intermediate value is what lets multiple providers
merge. Building that intermediate map collapses a duplicate YAML mapping key to its last value, before
`crates/core/src/git/remote.rs:52-76`'s custom `HostMap` `Visitor` (which walks `MapAccess` directly
and deliberately keeps every entry, comment at `remote.rs:41-48`) ever sees more than one entry.

`crates/core/src/config.rs`'s existing test `a_duplicate_git_hosts_key_in_yaml_fails_boot` (and the
companion `e2e_new_006_duplicate_host_fails_boot` in `git/remote.rs`) assert that a YAML file
declaring `github.com` twice under `git.hosts` fails to boot, naming the host and the word
"duplicate" — `crates/core/src/git/remote.rs:168`'s explicit post-parse check, which only has
something to check because the parse stage kept both entries. Under `figment::providers::Yaml`, the
second `github.com: anonymous` silently overwrote the first before that check ever ran: the test's
`.expect_err(...)` failed because loading succeeded with `hosts: [("github.com", "anonymous")]`
(single entry, not two).

This is not specific to `figment`: it is a structural property of any config library that merges
providers through a generic `Value` representation (the same collapse would happen with any other
`Value`-based merge library). It was undetectable before touching the code — the spec's own audit
(Section 9, item 7) could not have run `cargo test` against a `figment`-backed implementation that did
not yet exist.

**Resolution applied in this lot:** `ServerConfig::load`/`from_yaml` was **not** swapped to
`figment::providers::Yaml`. It still calls `serde_yaml::from_str` directly, which streams YAML map
entries into the target `Deserialize` impl without an intermediate keyed value, letting `HostMap`'s
custom `Visitor` keep every duplicate as it already relied on. The `etcetera`-backed XDG resolution
(the other half of DR-005) was applied as specified and is fully tested (see the DR-005 commit). The
now-unused `figment` dependency was removed from `Cargo.toml` and `crates/core/Cargo.toml` rather than
left in the tree unused, per the house rule against dependencies whose only usage doesn't exist.

**Invariant 14 note:** `a_duplicate_git_hosts_key_in_yaml_fails_boot` and
`e2e_new_006_duplicate_host_fails_boot` were kept exactly as they are; this drift entry is the reason
DR-005's YAML-parsing clause was not fully applied, rather than a rewrite of either test to tolerate
the behavior change (Invariant 14 forbids that without a Section 6.4 justification, and this discovery
happened after Section 6.4 was already closed).

**Resolution (2026-09-27): accepted as-is, closed.** `figment` is not adopted for `ServerConfig::load`.
Rationale for closing rather than pursuing option 2 below:

- `figment` was originally justified by DR-005 purely as a *parser swap*, not for its layering
  (`DDEC-002` already rejected adopting figment's `defaults < file < env < CLI` merge, the actual
  reason such a library exists). With the layering unused, `figment` buys this codebase **nothing**
  over `serde_yaml::from_str`: same YAML syntax, same `${VAR}` pre-expansion, same error path at the
  `ToolError::invalid_argument` boundary. The only measurable effect of adopting it here would have
  been the regression this entry documents.
- The duplicate-host guard is a genuine security-relevant check (`git/remote.rs:41-48`,
  `:168`): a config with `github.com` declared twice, once `github` and once `anonymous`, is exactly
  the kind of operator mistake that should fail boot loudly rather than silently apply "last one
  wins". Trading that guard away to satisfy a style-conformance debt item, for a library whose actual
  benefit is not used, is not a good trade.
- Option 2 (a `git.hosts`-specific pre-scan feeding a `figment`-based parse for everything else) was
  rejected: it adds a second parse path for one file to gain a library that is otherwise a drop-in
  replacement for what already exists, which is complexity with no corresponding capability gained.

**Status: resolved — won't-implement.** No further action needed; a future `/spec-debt` pass may
drop the `figment` clause from DR-005's canonical description so the compliance debt list stops
carrying a requirement this analysis shows is not worth meeting.
